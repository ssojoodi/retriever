# Saved hosts and last remote folders

## Summary
Remember successful connections and each host/account/port's last visited folder.

## Product behavior target
A native saved-host picker in Open Connection defaults to the most recent successful host. New connection clears fields; Forget removes local metadata. The remote folder is visible/editable and blank means server home. No password persistence or automatic launch connection.

## Architecture changes
Main-actor ConnectionHistory stores Codable metadata in UserDefaults; remote paths remain raw bytes. Dedicated connection sheet owns selection/editing. SFTP connect can restore a folder and fall back to home only on complete path-related server errors.

## UX acceptance criteria
Reconnect after relaunch without retyping; saved locations remain separate by username and port. Failed/cancelled connections do not replace saved entries. Deleted/inaccessible locations fall back visibly. Forget remains effective while browsing an existing connection.

## Automated test plan
Persistence, deduplication, identity separation, forget, corrupt data, raw path roundtrip; local-server restore/fallback/cancellation; native sheet selection and authenticated reconnect checks.

## Manual verification plan
Build and inspect actual connection sheet screenshot; use disposable local server for reconnect and last-folder behavior where possible. Do not seed real preferences with fake hosts for a screenshot.

## Assumptions and non-goals
Automatic local saving after success. No saved passwords, copied keys, stored trust decisions, background reconnect, or remote writes.
