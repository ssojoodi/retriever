# Native help

## Summary
Add accessible, offline guidance through the standard Help menu.

## Product behavior target
Users can find connection, fingerprint verification, downloading and cancellation instructions in a reusable native Help panel, with the actual keyboard shortcuts and current limitations.

## Architecture changes
AppDelegate owns one reusable Help panel. Help menu routes through the responder chain. Browser remains the single primary window; Help is an auxiliary panel. Include standard Hide Others and Services menus.

## UX acceptance criteria
Readable system typography, selectable text, no network dependency, correct shortcuts, window reuse and standard close behavior. Opening Help does not disconnect or interrupt transfers.

## Automated test plan
Build and AppKit checks for Help action routing, visible panel, one panel after repeated invocation, and closure. Existing window checks remain passing.

## Manual verification plan
Capture and inspect the Help panel in the native harness. Packaged-app workflow acceptance remains separate.

## Assumptions and non-goals
No website, support account, empty preferences or updates service. Guidance accurately describes single regular-file downloads and no overwrites.

## Evidence
`make check-windows` passed its unsigned build and all native checks, including Help responder routing, visibility, panel reuse and closure. Initial action name collided with NSApplication.showHelp; final code uses showRetrieverHelp. Inspected `artifacts/verification/help-window.png`: instructions are readable with native scrolling and matching shortcuts. This is harness evidence, not a packaged-app Help invocation. Existing core behavior was unchanged.
